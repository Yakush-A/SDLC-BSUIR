# Дополнительные спецификации

Модуль «Генератор отчётов листов персонажей» (Sheet Export) для Live D&D List

Версия 0.1, 15.11.2026, автор А.П. Якуш

Документ собирает требования, которые не относятся к конкретному прецеденту, а действуют на все прецеденты из `use-cases.md`: качество, ограничения, интерфейсы и правовые условия. Значения взяты из SRS v0.2 (`../srs/srs.md`); расхождения разрешаются в пользу SRS. Идентификаторы: `SS-NNN`.

## 1. Удобство использования

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SS-001 | Кнопка «Export to PDF» доступна с клавиатуры (Tab, Enter, Space) и имеет доступное имя для экранных дикторов | REQ-INT-008 | UC-01 |
| SS-002 | Контраст текста и фона кнопки не менее 4.5:1 в светлой и тёмной темах | REQ-INT-006 | UC-01 |
| SS-003 | Во время экспорта кнопка заблокирована и показывает «Generating…»; повторное нажатие не создаёт второй запрос | REQ-INT-007 | UC-01 |
| SS-004 | Сообщения пользователю фиксированы: «PDF сохранён» с именем файла и «Не удалось создать PDF. Повторите попытку.»; технические детали ошибки пользователю не показываются | REQ-FUNC-021, REQ-SEC-006 | UC-01, UC-07 |
| SS-005 | Предлагаемое имя файла `<имя персонажа>_<yyyy-MM-dd>.pdf`: символы `\ / : * ? " < > \|` и управляющие заменяются на `_`, имя усекается до 100 символов, пустое имя заменяется на `character` | REQ-FUNC-005 | UC-02 |
| SS-006 | Данные пользователей могут быть на кириллице и латинице; язык подписей PDF по умолчанию английский (решение OQ-4 ожидается) | SRS 2.4, OQ-4 | UC-01 |

## 2. Надёжность

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SS-010 | Недоступный, небезопасный или неподходящий портрет заменяется заглушкой, экспорт завершается успешно | REQ-REL-001 | UC-05, UC-01 |
| SS-011 | Для любых допустимых в БД данных экспорт завершается без необработанного исключения (проверка 1 000 случайных персонажей) | REQ-REL-002 | UC-01, UC-04 |
| SS-012 | Любой сбой (в том числе недоступность Renderer, таймаут, ошибка компиляции) возвращает ошибку в формате `ApiResponse` со статусом 5xx, 503 или 504; частичный PDF не отдаётся; временные файлы удаляются | REQ-REL-003 | UC-04, UC-07 |
| SS-013 | После 10 подряд неуспешных экспортов остальные эндпоинты проекта отвечают штатно; потребление памяти backend и Renderer после очистки не растёт более чем на 10% | REQ-REL-004 | UC-04 |
| SS-014 | Отмена диалога сохранения не создаёт файл, не вызывает ошибку и не отправляет запрос на сервер | REQ-FUNC-006 | UC-02 |

## 4. Безопасность и приватность

| ID | Спецификация | Источник | Прецеденты |
|----|--------------|----------|------------|
| SS-030 | Экспорт доступен только владельцу листа; без токена возвращается 401, для чужого листа ответ, принятый в проекте (403 или 404) | REQ-SEC-001 | UC-01 |
| SS-031 | Портрет загружается только по `http` и `https` на портах 80 и 443; запрещены loopback, частные, link-local, multicast и метаданные облака; не более 3 перенаправлений, 5 с, 5 МБ, 25 Мпикс | REQ-SEC-002, REQ-SEC-003 | UC-05 |
| SS-032 | Содержимое полей выводится как данные, а не как разметка или команды Typst | REQ-SEC-004 | UC-04 |
| SS-033 | В журналах backend и Renderer нет текстов полей, бинарных данных портрета, ссылки на портрет, манифеста и внутреннего токена | REQ-SEC-005 | UC-01, UC-10 |
| SS-034 | Renderer принимает только структурированные данные и `templateId` из allow-list; произвольный код Typst, файловые пути и сетевые адреса отклоняются; нет исходящего сетевого доступа; задание ограничено рабочим каталогом | REQ-SEC-006 | UC-04 |
| SS-035 | Порт Renderer не публикуется на хост; доступ только из внутренней сети и с service token | REQ-INT-011 | UC-04, UC-09 |

## 8. Интерфейсы

| ID | Интерфейс | Протокол и формат | Источник |
|----|-----------|-------------------|----------|
| SS-070 | Frontend → Backend | `GET /api/v1/characters/{id}/export/pdf`, JWT; ответ `application/pdf`, `Content-Disposition` (ASCII `filename` и `filename*`), `Cache-Control: no-store` | REQ-INT-004, SDD DV-IFC-01 |
| SS-071 | Backend → Typst Renderer | `POST /internal/v1/render`, `multipart/form-data` (`manifest` JSON и необязательный `portrait`), service token; ответ `application/pdf` | REQ-INT-011 |
| SS-072 | Backend → хост портрета | HTTP GET по проверенному URL | REQ-INT-010 |
| SS-073 | Frontend → файловая система | File System Access API; запасной вариант `<a download>` | REQ-FUNC-003, REQ-FUNC-007 |
| SS-074 | Оператор → Renderer | `GET /health/live`, `GET /health/ready` во внутренней сети | SDD DV-IFC-01 |
