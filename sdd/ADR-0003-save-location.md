# Сохранять PDF через File System Access API с запасным скачиванием

## Контекст и постановка задачи

PDF должен сохраняться в каталог, который пользователь выбирает в момент экспорта (C-3, REQ-FUNC-003, REQ-FUNC-004). Сервер не может писать на устройство пользователя, поэтому выбор каталога возможен только средствами браузера. Приложение — веб-интерфейс на React, работает по HTTPS.

Вопрос: каким механизмом браузера дать пользователю выбор каталога и имени файла и что делать там, где механизма нет?

## Драйверы решения

* Выбор каталога в момент экспорта (REQ-FUNC-003, REQ-FUNC-004)
* Доступность функции во всех браузерах (REQ-FUNC-007)
* Отмена не оставляет следов (REQ-FUNC-006), ошибка не оставляет пустой файл
* Отсутствие новых зависимостей frontend
* Ограничение браузера: диалог открывается только в ответ на действие пользователя

## Рассмотренные варианты

* `showSaveFilePicker` с запасным вариантом `<a download>`
* Только `<a download>`
* `showDirectoryPicker` с запоминанием каталога
* Обёртка (Electron/Tauri)

## Итог решения

Выбранный вариант: «`showSaveFilePicker` с запасным вариантом `<a download>`», потому что он единственный даёт настоящий выбор каталога и имени при каждом экспорте и при этом работает везде (где API нет, срабатывает обычное скачивание).

Порядок действий (важный): диалог вызывается сразу в обработчике клика, до сетевого запроса, иначе браузер потеряет «разрешение пользователя». Затем: сохранение отложенных правок → запрос PDF → запись в `createWritable()` → `close()`. При ошибке вызывается `abort()`, файл не появляется.

### Последствия

* Хорошо, потому что пользователь выбирает каталог и имя при каждом экспорте.
* Хорошо, потому что отмена диалога не требует обращений к серверу.
* Плохо, потому что в браузерах без `showSaveFilePicker` каталог определяется настройками браузера (OQ-1 к Заказчику).
* Плохо, потому что диалог открывается до генерации: пользователь выбирает файл, ещё не зная, успешен ли экспорт; поэтому при сбое выводится уведомление об ошибке, а файл не создаётся.
* Нейтрально, потому что нужен защищённый контекст (HTTPS или localhost), он уже обеспечен.

### Подтверждение

* Ручная проверка в Chrome/Edge и Firefox/Safari по `tests/manual/save-dialog.md` (REQ-FUNC-003, 004, 007).
* Автотест компонента: при отказе `showSaveFilePicker` (`AbortError`) запрос на сервер не отправляется, кнопка активна (REQ-FUNC-006).
* Проверка в прототипе: при ошибке сети после выбора файла файл на диске не создаётся (`abort()`).

## Плюсы и минусы вариантов

### `showSaveFilePicker` с запасным `<a download>`

* Хорошо, потому что настоящий выбор каталога и имени.
* Хорошо, потому что запасной путь обеспечивает работу во всех браузерах.
* Плохо, потому что два пути кода и два сценария проверки.

### Только `<a download>`

* Хорошо, потому что просто и работает везде.
* Плохо, потому что каталог выбирается только если пользователь включил запрос в настройках браузера, что не выполняет C-3.

### `showDirectoryPicker` с запоминанием каталога

* Хорошо, потому что можно один раз выбрать каталог.
* Плохо, потому что требует выдачи доступа ко всему каталогу, это шире, чем нужно, и Заказчик просил выбор «в момент экспорта».
* Плохо, потому что поддержка браузеров не лучше.

### Обёртка (Electron/Tauri)

* Хорошо, потому что полный доступ к файловой системе.
* Плохо, потому что превращает веб-проект в настольное приложение, что выходит за рамки модуля.
